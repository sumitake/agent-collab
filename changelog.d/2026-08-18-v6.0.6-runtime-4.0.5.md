### agent-collab 6.0.6 — 2026-08-18

#### Fixed

- Ship provider runtime `4.0.5`, repairing the 4.0.4 readiness crash that
  forced the v6.0.5 activation rollback: a defective candidate probe now
  degrades route-locally with a bounded exception-class diagnostic
  (`readiness_probe_crashed_<class>`) instead of failing the whole
  zero-inference snapshot as an opaque `provider_error`.
- Tolerate ACP display-title drift: tool titles are display metadata
  (identity is the toolCallId; kind conflicts and status regressions still
  drop identity), and read/search evidence admission is kind-primary with a
  quoted-span-aware mutation/meta deny scan. Authorization keeps strict
  title+kind agreement. This ends the receipt-less-advisory failure mode
  introduced by grok CLI 1.0.5's decorated titles.
- Tolerate catalog metadata drift: OpenCode standard-profile selection
  resolves role-tagless catalogs (GLM 5.x) through a deterministic
  newest-dominant ladder instead of failing the lineage as ambiguous.
- Fail-safe failure envelopes: an invalid composed status/code pairing
  degrades to the canonical typed `protocol_error` response, and the
  no-route path reports plain unavailability absent a capability-drift
  selection.
- Public client teardown tolerance: process-group teardown proof runs on
  its own bounded budget (no longer starved by the consumed request
  deadline), and a cleanly exited runtime with a valid collected response
  is never voided by unproven teardown or reap errors — the frequent false
  `teardown_error` on long Agy calls is gone. Private-tmp cleanup residue
  after a valid response is recorded, not converted into failure.
- intent-check requests standard quality/effort on its dedicated verify
  intent, matching the operator-adjudicated effort floors.

#### Safety

- The routing source advances with the workspace verify-intent change; the
  wire descriptor is otherwise unchanged from v6.0.5's compatible evolution.
  Authorization strictness, location containment, post-session
  source-mutation detection, and deny-by-default permissions are unchanged.
  No retry, replay, fallback transport, or provider default was added.
